# Архитектура системы TelegramWarden

Документ описывает техническое устройство, внутренние модули, алгоритмы обработки данных и схемы взаимодействия компонентов TelegramWarden.

---

## 1. Обзор архитектуры

TelegramWarden построен по принципу гибридного сервиса, объединяющего высокопроизводительный асинхронный Telegram-бот (aiogram 3), REST API бэкенд (FastAPI), встроенную WebApp панель управления и многоуровневый конвейер модерации контента.

```
                  +----------------------------------------------+
                  |               Telegram Clients               |
                  +----------------------+-----------------------+
                                         |
                       Updates / WebApp  | HTTPS / MTProto
                                         v
                  +----------------------------------------------+
                  |         TelegramWarden Unified Engine        |
                  |                                              |
                  |  +-------------------+  +-----------------+  |
                  |  | aiogram 3 Bot     |  | FastAPI Backend |  |
                  |  | (Polling/Webhook) |  | (Port 2009)     |  |
                  |  +---------+---------+  +--------+--------+  |
                  +------------|---------------------|-----------+
                               |                     |
                +--------------+---------------------+--------------+
                |                                                   |
                v                                                   v
+-------------------------------+                   +-------------------------------+
|     Data & Storage Layer      |                   |    Multi-Stage Pipeline       |
|                               |                   |                               |
| - PostgreSQL 16 (Relational)  |                   | 1. Regex & Homoglyphs Pre-Pass|
| - Redis 7 (Tokens, Captcha)   |                   | 2. Risk Heuristics (0 tokens) |
| - SQLAlchemy Async Engine     |                   | 3. Local NSFW ONNX (CPU 12ms) |
+-------------------------------+                   | 4. Primary AI: Llama 3.1 70B  |
                                                    | 5. Fallback AI: Gemini 1.5    |
                                                    +-------------------------------+
```

## 3. Схема конвейера модерации текста

Каждое текстовое сообщение проходит через каскадный конвейер, оптимизированный для минимизации задержек и экономии токенов:

```
[Входящее сообщение]
         |
         v
[Этап 1: Нормализация и очистка]
  - Удаление Zero-Width символов, Zalgo, мягких переносов
  - Транслитерация маскировочных символов (IPA, Komi, греческий)
  - Извлечение скрытых ссылок и Telegram-юзернеймов
         |
         v
[Этап 2: Эвристический скоринг риска (RiskScorer)]
  - Проверка репутации и возраста аккаунта
  - Поиск стоп-слов, крипто-скама и фишинговых паттернов
  - Если риск < 15% и пользователь проверен -> Пропуск без вызова LLM (0 ms, 0 токенов)
         |
         v
[Этап 3: Нейросетевой анализ (AIDispatcher)]
  - Первичный провайдер: NVIDIA NIM (Llama 3.1 70B Instruct)
  - Резервный провайдер: Google Gemini 1.5 Flash (автопереключение при таймауте)
  - Структурированный JSON-вывод вердикта (категория, уверенность, причина)
         |
         v
[Этап 4: Применение политик чата (SanctionsExecutor)]
  - Режим "Только админам": Отправка интерактивной карточки в журнал
  - Режим "Нейросеть": Немедленное удаление, варн, мут или бан
  - Запись события в AuditLog
```

## 4. Схема конвейера модерации медиа

Медиафайлы проверяются локально на CPU без отправки в сторонние платные Vision API:

```
[Входящее медиа (Фото / Видео / Кружочек / Стикер)]
         |
         v
[1. Перцептивный хеш (pHash)] -> Совпадение с базой спама -> Немедленный бан (1 ms)
         |
         v
[2. Выборка ключевых кадров (Keyframe Sampler)]
         |
         v
[3. Декодер QR-кодов] ---------> Обнаружение скам-ссылок -> Варн/Удаление
         |
         v
[4. Yahoo Open-NSFW (ONNX)] ---> Обнаружение обнажения (>70%) -> Немедленный бан (12 ms)
         |
         v
[5. Локальный OCR Текст] ------> Обнаружение рекламных ссылок на баннерах -> Варн
```

## 6. Безопасность и отказоустойчивость

1. **Аутентификация Telegram WebApp**: Все запросы к REST API защищены валидацией HMAC-SHA256 подписи Telegram `initData` с использованием секретного ключа бота. Подделка запросов невозможна.
2. **Fail-Open архитектура**: При временной недоступности всех LLM-провайдеров система не блокирует чат, а логирует событие и пропускает подозрительные сообщения администраторам.
3. **Защита от Rate Limit**: Запросы к Telegram Bot API балансируются с учетом лимитов платформы (30 сообщений в секунду на бота, 1 сообщение в секунду в одну группу).

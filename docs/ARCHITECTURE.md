# Архитектура системы TelegramWarden

Документ описывает техническое устройство, внутренние модули, алгоритмы обработки данных, схемы конвейеров модерации и структуры базы данных TelegramWarden версии v1.1.1-stable.

---

## 1. Обзор архитектуры

TelegramWarden построен по принципу гибридного сервиса, объединяющего высокопроизводительный асинхронный Telegram-бот (aiogram 3), REST API бэкенд (FastAPI), встроенную WebApp панель управления и многоуровневый конвейер модерации контента.

```
                  +----------------------------------------------+
                  |               Telegram Clients               |
                  +----------------------+-----------------------+
                                         |
                       Updates / WebApp  | HTTPS / MTProto
                                         v
                  +----------------------------------------------+
                  |         TelegramWarden Unified Engine        |
                  |                                              |
                  |  +-------------------+  +-----------------+  |
                  |  | aiogram 3 Bot     |  | FastAPI Backend |  |
                  |  | (Polling/Webhook) |  | (Port 2009)     |  |
                  |  +---------+---------+  +--------+--------+  |
                  +------------|---------------------|-----------+
                               |                     |
                +--------------+---------------------+--------------+
                |                                                   |
                v                                                   v
+-------------------------------+                   +-------------------------------+
|     Data & Storage Layer      |                   |    Multi-Stage Pipeline       |
|                               |                   |                               |
| - PostgreSQL 16 (Relational)  |                   | 1. Regex & Homoglyphs Pre-Pass|
| - Redis 7 (Tokens, Captcha)   |                   | 2. Risk Heuristics (0 tokens) |
| - SQLAlchemy Async Engine     |                   | 3. Local NSFW ONNX (CPU 12ms) |
+-------------------------------+                   | 4. Tier-1 Jev Triage (150ms)  |
                                                    | 5. Primary AI: DeepSeek Chat  |
                                                    | 6. Fallback AI: Groq Llama 3.3|
                                                    +-------------------------------+
```

## 3. Схема конвейера модерации текста

Каждое текстовое или отредактированное сообщение проходит через каскадный конвейер, оптимизированный для минимизации задержек и экономии токенов:

```
[Входящее / Отредактированное сообщение]
         |
         v
[Этап 1: Проверка ограничений чата]
  - Ночной режим (Тихий час по часовому поясу группы)
  - Ограничение медиа для новичков (Newbie Lock)
         |
         v
[Этап 2: Нормализация и очистка]
  - Удаление Zero-Width символов, Zalgo, мягких переносов
  - Транслитерация маскировочных символов (IPA, Komi, греческий)
  - Извлечение скрытых ссылок и Telegram-юзернеймов
         |
         v
[Этап 3: Эвристический скоринг риска (RiskScorer)]
  - Проверка репутации и возраста аккаунта
  - Поиск стоп-слов на границах слов (по чистому и каноническому тексту)
  - Если риск < 15% и пользователь проверен -> Пропуск без вызова LLM (0 ms, 0 токенов)
         |
         v
[Этап 4: Нейросетевой анализ (AIDispatcher)]
  - Tier-1 (Рекомендуется для продакшена, JEV_ENABLED): скоростной триаж TypeSafe Jev (System One).
    Дискриминативная модель оценивает вероятность нарушения (noul) и распределение по 9
    категориям (choice) за один сетевой запрос (~150-400 мс).
    * Fast-Pass: сообщения с вероятностью нарушения ниже порога (по умолчанию 0.03)
      пропускаются мгновенно без обращения к большой LLM, экономя 80-90% токенов.
    * Defense-Only: Jev используется исключительно для безопасного ускорения и удешевления пропуска
      чистого трафика. Любые карательные санкции требуют развернутого обоснования от большой LLM.
    * Метрики: каждый вызов фиксируется в logs/jev_triage.jsonl для калибровки порогов.
    * Сбои и таймауты: прозрачный fallback на Tier-2 без задержки модерации.
  - Tier-2: первичный генеративный провайдер DeepSeek Chat (OpenAI-compatible)
  - Резервный провайдер: Groq Llama 3.3 70B (автопереключение при таймауте)
  - Калибровка уверенности (сглаживание 1%/99% экстремумов)
         |
         v
[Этап 5: Применение политик чата и RBAC]
  - Режим "Только админам": Отправка интерактивной карточки в журнал
  - Режим "Нейросеть": Немедленное удаление, варн, мут или бан
  - Запись события в AuditLog
```

## 4. Схема конвейера модерации медиа

Медиафайлы проверяются локально на CPU без отправки в сторонние платные Vision API:

```
[Входящее медиа (Фото / Видео / Кружочек / GIF / Стикер)]
         |
         v
[1. Проверка Newbie Media Lock] -> Возраст аккаунта < N часов -> Удаление
         |
         v
[2. Перцептивный хеш (pHash)] ---> Совпадение с базой спама -> Немедленный бан (1 ms)
         |
         v
[3. Выборка ключевых кадров (Keyframe Sampler для видео и GIF)]
         |
         v
[4. Декодер QR-кодов] -----------> Обнаружение скам-ссылок -> Варн/Удаление
         |
         v
[5. Yahoo Open-NSFW (ONNX)] ----> Обнаружение обнажения (>70%) -> Немедленный бан (12 ms)
         |
         v
[6. Локальный OCR Текст] -------> Обнаружение рекламных ссылок на баннерах -> Варн
```

## 6. Безопасность и отказоустойчивость

1. **Аутентификация Telegram WebApp**: Все запросы к REST API защищены валидацией HMAC-SHA256 подписи Telegram `initData` с использованием секретного ключа бота. Запросы без подписи или с истекшим `auth_date` отклоняются с кодом `401 Unauthorized`.
2. **RBAC контроль в Telegram**: Все интерактивные действия (снятие варна, бан, мут, подтверждение ложного срабатывания) требуют явного подтверждения прав администратора через `is_chat_admin`.
3. **Fail-Open архитектура**: При временной недоступности всех LLM-провайдеров система не блокирует чат, а логирует событие и пропускает подозрительные сообщения администраторам.
4. **Защита от Rate Limit**: Запросы к Telegram Bot API балансируются с учетом лимитов платформы (30 сообщений в секунду на бота, 1 сообщение в секунду в одну группу).
5. **Безопасность Tier-1 триажа (Defense-Only)**: Модель TypeSafe Jev выполняет роль безопасного ускорителя (Fast-Pass для заведомо чистых реплик). Ни одна санкция или блокировка пользователя не может быть вынесена на основании одних лишь вероятностей Jev. Все подозрительные события, сообщения со ссылками и критические категории (фишинг, контрабанда) передаются на полноценный разбор в DeepSeek или Groq для формирования аргументированного вердикта на русском языке.
